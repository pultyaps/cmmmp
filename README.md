# ВМММФП — главная страница и админка

## 1. Редактирование в Pinegrow

Откройте **папку `site`** как проект, затем откройте **`index.html`**. Главная открывается как обычный HTML. Для черновой работы над разметкой можно открыть её напрямую, без Node.js и без админки.

| Файл | Что в нём |
| --- | --- |
| `site/index.html` | Главная. Здесь можно править разметку внутри `body`, перемещать секции и редактировать статические тексты. |
| `site/assets/site.css` | Стили исходной страницы для аккордеонов и всплывающих окон. |
| `site/assets/tailwind-config.js` | Цвета, шрифты и прочие настройки Tailwind из исходного файла. |
| `site/assets/site.js` | Поведение сайта, получение данных, фильтры, поиск и заполнение карточек. |
| `site/assets/content-defaults.js` | Пример данных для локального HTML и статического предпросмотра. |
| `site/pages/example.html` | Шаблон дополнительной страницы с общей шапкой, подвалом и стилями. |

На карточках преподавателя и руководителя можно менять расположение полей и классы в HTML. Сохраняйте `data-person-template`, `data-person-field` и `data-person-tags`, чтобы скрипт нашёл элементы. Сохраняйте ID контейнеров динамических секций, например `faculty-grid` или `news-grid`. Во время предпросмотра данные подставляются автоматически. Тексты с привязкой к данным меняются в админке. Шаблоны карточек новостей, курсов, документов и FAQ находятся в `assets/site.js`.

Исходный дизайн использует Tailwind CDN и Google Fonts. Для просмотра в исходном оформлении браузеру нужен доступ к этим ресурсам. Визуальный редактор также может менять классы элементов при правке разметки, даже если сами файлы стилей не редактируются.

## 2. Добавление страницы

1. Сделайте копию `site/pages/example.html`. Назовите её латиницей, например `summer-school.html`.
2. Откройте копию в Pinegrow. Поменяйте заголовок вкладки, описание в `head` и содержимое `main`.
3. Добавьте ссылку `pages/summer-school.html` в настольное и мобильное меню главной, если страница должна быть доступна из шапки.
4. Запустите из корня проекта `npm run sync-pages`, когда меняете шапку или подвал. Команда копирует два общих фрагмента из главной во все страницы, поправляет относительные ссылки и сохраняет содержимое `main`. Не удаляйте комментарии `shared:header` и `shared:footer`.

На работающем сервере ваша страница будет доступна по адресу `/pages/summer-school.html`. Изображения и PDF можно положить в `site/media/`. Используйте имена из латинских букв, цифр, дефиса или подчёркивания и одно расширение. Из главной путь будет `media/файл`, а из дополнительной страницы — `../media/файл`. В админке для PDF используйте путь от корня, например `/media/booklet.pdf`, или HTTPS-ссылку.

## 3. Запуск бесплатной админки

В комплект входит собственная админка без платных лицензий и внешних аккаунтов. Нужен **Node.js 22+**. Для локального запуска не требуются MySQL и PHP. Команды выполняются в PowerShell или терминале из папки проекта, где лежит `package.json`.

```text
npm run account -- owner publisher
npm run account -- anna editor
npm run account -- ivan publisher
npm start
```

Используйте свои логины. Каждая команда `account` создаёт отдельную учётную запись и один раз показывает сгенерированный пароль. Сохраните его и передайте соответствующему человеку. Откройте `http://localhost:3000/` для сайта и `http://localhost:3000/admin/` для входа. Открывайте именно тот адрес, который указан в `SITE_ORIGIN` или настройках по умолчанию.

- **editor** может редактировать и сохранять общий черновик.
- **publisher** может редактировать общий черновик и публиковать его.
- Предпросмотр показывает последний сохранённый черновик. Открыть его можно из админки после входа.
- Если другой пользователь сохранил изменения раньше вас, сервер отклонит устаревшее сохранение. Скопируйте свои изменения перед обновлением страницы и внесите их в свежий черновик.
- В админке есть преподаватели, руководители, новости и семинары, документы, контакты, курсы и FAQ. Тексты и структура статических разделов по-прежнему находятся в HTML.

Пароли хранятся в виде хешей в `accounts.json`, а правки — в `data/content.json`. После добавления аккаунта перезапустите сервер. Чтобы отозвать доступ, удалите соответствующую запись из файла аккаунтов на остановленном сервере и запустите его снова.

## 4. Публикация на собственном хостинге

- **С админкой:** нужен VPS или тариф с Node.js 22+. На сервере установите `SITE_ORIGIN=https://ваш-домен.example` без завершающего слеша, настройте HTTPS и задайте `DATA_DIR` и `ACCOUNTS_FILE` на постоянные пути вне публичной папки сайта. Запускайте один экземпляр приложения командой `npm start`. По умолчанию приложение слушает `127.0.0.1:3000`. Если провайдер требует другой адрес или порт, доступны переменные `HOST` и `PORT`.
- **Без админки:** можно разместить одну папку `site` на статическом хостинге. Там будут данные из `content-defaults.js`.
- При обновлении разметки, стилей или скриптов копируйте исходные файлы проекта и сохраняйте постоянные пути данных и аккаунтов. Для резервной копии сохраните `content.json`, файл аккаунтов и папку `site/media`. Старый `data/content.json` из пакета ФММП для Node.js можно перенести. Новые списки, отсутствующие в старых данных, заполнятся из исходного сайта.
- Если позже понадобится внешняя CMS, точка подключения находится в `loadContent()` в `site/assets/site.js`. Фронтенд уже читает JSON через `GET /api/content`. Скрипты админки и сайт используют разные маршруты. Публичный API отдаёт только опубликованные записи.
- Форма заявки на сайте демонстрационная. Она не отправляет сообщения.
